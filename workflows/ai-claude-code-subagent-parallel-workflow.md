# Claude Code 서브에이전트 병렬 실행 워크플로우

> 하나의 세션에서 여러 작업을 동시에 처리하는 실전 패턴

## 개요

Claude Code의 서브에이전트 기능을 쓰면 오래 걸리는 작업을 백그라운드로 넘기고, 메인 세션에서는 다른 일을 계속할 수 있어요. 프론트엔드 리팩터링과 백엔드 테스트 작성을 동시에 진행하거나, 대규모 코드베이스 분석과 문서화를 병렬로 처리하는 게 가능해집니다.

이 워크플로우는 서브에이전트를 언제, 어떻게 써야 효과적인지 정리한 실전 가이드예요.

## 사전 준비

- Claude Code 최신 버전 (서브에이전트 지원)
- 병렬 처리가 가능한 태스크 목록
- 작업별 독립적인 컨텍스트 (공유 상태가 적을수록 효과적)

## 서브에이전트 vs 순차 실행: 언제 쓸까요

| 상황 | 권장 방식 |
|------|-----------|
| 다음 단계가 이전 결과에 의존 | 순차 실행 |
| 서로 독립된 파일/모듈 작업 | 서브에이전트 병렬 |
| 대규모 코드베이스 분석 | 서브에이전트 (영역 분담) |
| 테스트 + 구현 동시 진행 | 서브에이전트 병렬 |
| 빠른 팩트체크나 단순 조회 | 순차 실행 (오버헤드 있음) |

## Step 1: 작업 분리 설계

병렬화하기 전에 태스크를 독립 단위로 나눠요.

```
# 좋은 분리 예시 (서로 의존성 없음)
태스크 A: frontend/components/ 전체 타입 에러 수정
태스크 B: backend/api/ 엔드포인트 유닛 테스트 작성
태스크 C: docs/ 마크다운 문서 업데이트

# 나쁜 분리 예시 (의존성 있음)
태스크 A: 새 API 엔드포인트 설계
태스크 B: 태스크 A 결과물 기반으로 프론트엔드 연동  # A가 끝나야 시작 가능
```

작업 분리 프롬프트:

```
다음 요청을 독립적으로 처리 가능한 서브태스크 3개로 분리해줘.
각 태스크는 다른 태스크 결과물에 의존하지 않아야 해.

요청: [전체 작업 설명]
```

## Step 2: 포어그라운드 vs 백그라운드 선택

### 포어그라운드 서브에이전트 (기본)

결과를 기다렸다가 다음 단계에서 쓸 때 사용해요.

```
# 리서치 → 구현 패턴
프롬프트: "이 코드베이스의 인증 흐름을 분석해서 보안 취약점을 찾아줘.
           결과를 바탕으로 수정 계획을 세울게."
```

서브에이전트가 완료되면 메인 세션에서 결과를 받아서 다음 작업을 진행해요.

### 백그라운드 서브에이전트

서로 완전히 독립된 작업에 써요. `Ctrl+B`로 백그라운드 전환.

```
프롬프트: "3개의 서브에이전트를 동시에 실행해줘.
- 에이전트 1: src/components/ 전체 접근성(a11y) 이슈 목록 작성
- 에이전트 2: src/api/ 엔드포인트별 응답 시간 측정 및 병목 찾기
- 에이전트 3: 미사용 의존성 패키지 목록 작성

각 에이전트는 독립적으로 실행하고, 완료되면 결과를 알려줘."
```

## Step 3: 진행 상황 모니터링

```bash
# 현재 실행 중인 서브에이전트 확인
/tasks

# 특정 태스크 상태 확인
/tasks <task-id>

# 완료된 태스크 결과 가져오기
/tasks <task-id> result
```

백그라운드 에이전트가 완료되면 메인 세션에 알림이 와요. 그때 결과를 확인하고 다음 단계로 넘어가면 돼요.

## Step 4: 결과 통합

서브에이전트들이 모두 완료되면 결과를 합쳐서 최종 작업을 수행해요.

```
프롬프트: "3개 에이전트 작업이 완료됐어.
각 결과를 검토하고 다음을 수행해줘:
1. 접근성 이슈 중 우선순위 높은 것 3개 수정
2. API 병목 구간 최적화 PR 초안 작성
3. package.json에서 미사용 패키지 제거 및 커밋"
```

## 실전 패턴 모음

### 패턴 1: 대규모 코드베이스 분석

```
"이 레포를 4개 영역으로 나눠서 동시에 분석해줘.
- 에이전트 1: frontend/ 코드 품질과 타입 안전성
- 에이전트 2: backend/ 성능 병목과 N+1 쿼리
- 에이전트 3: infra/ 설정 파일 보안 이슈
- 에이전트 4: tests/ 커버리지 공백 분석

각자 완료되면 결과 파일을 /tmp/analysis/{영역}.md에 저장해줘."
```

### 패턴 2: 테스트 병렬 작성

```
"다음 5개 모듈의 유닛 테스트를 동시에 작성해줘.
각 에이전트는 하나의 모듈만 담당:
- user-service.ts
- payment-service.ts  
- notification-service.ts
- auth-service.ts
- analytics-service.ts

테스트 파일은 각 서비스 옆에 .test.ts로 저장."
```

### 패턴 3: 리서치 후 구현 (순차 + 병렬 혼합)

```
# Phase 1 (포어그라운드 - 순차)
"현재 의존성 버전을 분석하고 업그레이드 위험도를 평가해줘."

# 결과 확인 후...

# Phase 2 (백그라운드 - 병렬)
"평가 결과를 바탕으로:
- 에이전트 1: 저위험 의존성 업그레이드 + 테스트
- 에이전트 2: 중간위험 의존성 호환성 확인 스크립트 작성
동시에 진행해줘."
```

## 서브에이전트 효과적으로 쓰는 팁

| 팁 | 이유 |
|----|------|
| 에이전트 수를 명시 ("5개 병렬로") | 막연한 지시보다 명확한 숫자가 더 잘 동작 |
| 각 에이전트 결과 저장 경로 지정 | 통합 단계에서 결과 수집이 쉬워짐 |
| 공유 파일 동시 수정 피하기 | 충돌 방지 — 에이전트마다 작업 영역 분리 |
| 복잡한 태스크는 단계별 명세서 첨부 | AGENTS.md나 태스크 문서 참조 유도 |

## 문제 해결

| 증상 | 해결 |
|------|------|
| 에이전트가 서로 같은 파일 수정 | 작업 영역 명확히 분리 후 재시도 |
| 백그라운드 에이전트 알림 없음 | `/tasks`로 수동 확인 |
| 결과가 기대와 다름 | 각 에이전트에 더 구체적인 성공 기준 명시 |
| 컨텍스트 창 초과 | 에이전트당 작업 범위를 더 좁게 분리 |
