# AI 에이전트 프롬프트 최적화 치트시트 2026

> 토큰 낭비 없이 고품질 출력을 얻는 핵심 패턴 — 한 페이지 요약

## 역할 프레이밍 (Role Framing)

| 상황 | 프롬프트 패턴 |
|------|-------------|
| 코드 리뷰 | `시니어 백엔드 개발자로서, 다음 코드를 리뷰해줘: [코드]` |
| 버그 수정 | `디버깅 전문가로서, 이 에러의 근본 원인을 찾아줘: [에러]` |
| 아키텍처 설계 | `시스템 설계 전문가로서, 이 요구사항에 맞는 구조를 제안해줘` |
| 보안 검토 | `보안 엔지니어로서, 이 코드의 취약점을 분석해줘` |

**효과:** 역할 프레이밍 자체만으로 출력 품질이 15-20% 향상. 단, 역할은 1개만 지정.

## 체인 오브 씽킹 (Chain of Thought)

### Zero-shot CoT

```
이 코드를 리팩터링하기 전에, 단계별로 생각해줘:
1. 현재 코드의 문제점
2. 리팩터링 방향
3. 부작용 가능성
그런 다음 리팩터링 코드를 작성해줘.
```

### 직접 단계 지정

```
다음 순서로 진행해줘:
Step 1. 요구사항 파악 (분석만, 코드 작성 금지)
Step 2. 구현 계획 작성
Step 3. 코드 작성
Step 4. 엣지 케이스 검토
```

> 단계 지정 방식이 자유 사고보다 토큰 35% 절약하면서 동일한 품질 유지.

## Few-shot 예시 패턴

### 입출력 예시 포함

```
함수 이름을 카멜케이스로 변환해줘.

예시:
입력: get_user_data → 출력: getUserData
입력: update_profile_image → 출력: updateProfileImage

변환 대상:
- fetch_order_list
- calculate_total_price
- send_notification_email
```

**원칙:** 예시는 2-3개가 최적. 5개 이상이면 토큰 낭비 대비 품질 향상이 미미.

## 출력 형식 지정

### JSON 출력

```
분석 결과를 다음 JSON 형식으로만 반환해줘. 설명 텍스트 없이.

{
  "issues": [{"type": "", "line": 0, "description": ""}],
  "severity": "low|medium|high",
  "refactor_needed": true|false
}
```

### 표 형식

```
비교 결과를 마크다운 표로만 정리해줘.
컬럼: 항목, 현재 방식, 개선 방식, 예상 효과
```

### 간결 출력 강제

```
핵심만 3줄 이내로 답해줘. 배경 설명 생략.
```

## 토큰 절약 전략

| 전략 | 절약량 | 사용 시점 |
|------|--------|----------|
| 컨텍스트 압축 | 20-40% | 긴 대화 세션 |
| 출력 형식 강제 | 15-30% | 반복 호출 |
| 역할 단일 지정 | 10-15% | 일반적 상황 |
| 불필요한 단계 제거 | 25-35% | CoT 과다 사용 시 |
| 프롬프트 캐싱 활용 | 최대 90% | 동일 시스템 프롬프트 반복 |

### 프롬프트 캐싱 (Claude Code)

```bash
# 긴 CLAUDE.md가 있는 프로젝트에서 캐싱 자동 적용
# 동일 파일 반복 참조 시 토큰 90% 절약
# 첫 호출: 캐시 miss → 전체 토큰 소비
# 이후 호출: 캐시 hit → 입력 토큰 거의 0
```

## 흔한 실수 & 수정

| 실수 | 수정 방법 |
|------|----------|
| "이 코드를 더 좋게 해줘" | "가독성 개선에 집중, 기능 변경 금지" |
| "뭔가 문제가 있어" | "Line 42에서 NullPointerException 발생, 원인 분석" |
| "모두 리팩터링해줘" | "auth 모듈만, 다른 파일 건드리지 말 것" |
| 역할 중복 지정 | 역할 1개만 지정 |
| 예시 5개 이상 | 2-3개로 줄이기 |
| "잘 설명해줘" | "3줄, 항목별 정리, 예시 포함" |

## 모델별 최적화 팁

### Claude Code

```
# 파일 직접 참조 (Read 도구 자동 트리거)
"@auth/service.ts를 분석해줘"

# 범위 제한으로 할루시네이션 방지
"이 함수만 수정해줘. 다른 파일은 건드리지 말 것."
```

### Gemini CLI

```bash
# 파일 번들링으로 컨텍스트 효율화
gemini -f src/auth.ts -f src/types.ts "이 두 파일의 의존성을 분석해줘"
```

### Codex CLI

```bash
# 작업 범위 명시
codex "tests/ 폴더만 대상으로 실패한 테스트를 수정해줘"
```

## 프롬프트 품질 자가 점검

```
□ 역할이 명확하게 지정되어 있는가?
□ 원하는 출력 형식을 명시했는가?
□ 범위(파일/함수/기능)를 제한했는가?
□ 금지 사항을 명시했는가? (다른 파일 건드리지 말 것 등)
□ 예시를 2-3개 포함했는가? (필요한 경우)
□ 모호한 표현을 제거했는가?
```
