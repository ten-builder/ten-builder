# AI 에이전트 Anti-Patterns 치트시트 2026

> AI 코딩 에이전트 사용 시 생산성을 갉아먹는 7가지 반패턴과 올바른 대안 — 한 페이지 요약

## 1. 프롬프트 터널링 (Prompt Tunneling)

결과 확인 없이 메시지를 계속 쌓는 패턴.

| 반패턴 | 올바른 방법 |
|--------|------------|
| 결과 보지 않고 다음 메시지 전송 | 단계별 확인 후 다음 지시 |
| 에러 무시하고 계속 진행 | 에러 발생 시 즉시 원인 파악 |
| 컴파일 없이 다음 기능 추가 | 각 단계 빌드/테스트 통과 확인 |

## 2. 유령 컨텍스트 (Ghost Context)

에이전트가 이전 대화를 기억한다고 가정하는 패턴.

```markdown
# 잘못된 방식
"지난번에 만든 그 함수에 캐싱 추가해줘"

# 올바른 방식
"auth/utils.ts의 validateToken 함수에 Redis 캐싱 추가.
TTL은 15분, 키 형식은 'token:{userId}'"
```

**핵심:** CLAUDE.md에 프로젝트 컨텍스트를 문서화하면 세션 간 일관성 유지.

## 3. 거대 프롬프트 (Mega-Prompt)

한 번에 너무 많은 기능을 요청하는 패턴.

| 반패턴 | 올바른 방법 |
|--------|------------|
| "로그인, 회원가입, OAuth, 이메일 인증을 한번에 만들어줘" | 기능을 5~10분 단위 태스크로 분해 |
| 3개 이상 파일 동시 변경 요청 | Plan Mode 활용 후 단계적 실행 |
| 스펙 없이 "알아서 해줘" | 요구사항 먼저 작성 → 에이전트 검토 |

## 4. 제로 검증 (Zero Verification)

AI 생성 코드를 확인 없이 배포하는 패턴.

```bash
# 올바른 검증 파이프라인
1. 유닛 테스트 실행
   npm test -- --coverage

2. 타입 체크
   npx tsc --noEmit

3. 린트
   npx eslint src/ --max-warnings=0

4. 빌드 확인
   npm run build
```

**규칙:** AI가 생성한 코드는 주니어 개발자 코드처럼 반드시 리뷰.

## 5. 권한 맹신 (Security Bypass)

에이전트 권한을 무제한으로 허용하는 패턴.

| 반패턴 | 올바른 방법 |
|--------|------------|
| 모든 도구 사용 허용 | 프로젝트별 허용 도구 명시 |
| 프로덕션 DB 접근 허용 | 읽기 전용 스테이징 환경만 제공 |
| 비밀 키를 컨텍스트에 직접 포함 | 환경변수로 분리, .env.example 사용 |

```yaml
# CLAUDE.md 권한 설정 예시
allowed_tools:
  - read_file
  - write_file
  - run_bash (스테이징 환경만)
denied_actions:
  - production DB 수정
  - 외부 API 직접 호출 (승인 없이)
```

## 6. 컨텍스트 오염 (Context Contamination)

오래된 실패 시도들이 새 시도를 방해하는 패턴.

```bash
# 컨텍스트가 너무 길어졌을 때
/compact          # 대화 압축
/rewind           # 특정 시점으로 되돌리기
/clear            # 새 세션 시작 (복잡한 기능 전환 시)

# 권장: 기능 단위로 세션 분리
- 새 기능 → 새 세션
- 버그 수정 → 별도 세션
- 리팩토링 → 독립 세션
```

## 7. 검증 루프 생략 (Plan-Skip)

계획 없이 바로 구현에 돌입하는 패턴.

```
3개 이상 파일을 수정하는 작업 시 권장 흐름:

1. 요구사항 설명 → 에이전트에게 계획 작성 요청
2. 계획 검토 및 수정
3. 단계별 구현 승인
4. 각 단계 후 테스트 확인
```

**Plan Mode 활용 시:** `/plan` 커맨드 또는 "코드를 작성하기 전에 계획만 보여줘" 프롬프트 패턴.

## 반패턴 자가 진단 체크리스트

- [ ] 에이전트 응답을 항상 확인하고 다음 지시를 내리고 있는가?
- [ ] CLAUDE.md에 핵심 컨텍스트가 문서화되어 있는가?
- [ ] 태스크를 10분 이내 단위로 분해했는가?
- [ ] 모든 변경사항에 테스트가 있는가?
- [ ] 에이전트 권한을 최소 필요 수준으로 제한했는가?
- [ ] 컨텍스트가 길어지면 /compact를 사용하는가?
- [ ] 복잡한 변경 전 계획을 먼저 확인하는가?

## 흔한 실수 → 빠른 해결

| 상황 | 해결 방법 |
|------|----------|
| 에이전트가 같은 실수를 반복 | CLAUDE.md에 금지 패턴 명시 |
| 코드가 점점 복잡해짐 | /compact 후 새 태스크로 분리 |
| 테스트가 통과하지 않음 | "테스트를 먼저 통과시키는 것에만 집중" |
| 의도와 다른 코드 생성 | 요구사항을 코드로 표현 (타입, 인터페이스) |
| 컨텍스트 창 부족 | git worktree로 독립 체크아웃 |
