# VS Code Agents 창 기반 AI 개발 플레이북

> VS Code 1.120에서 Stable로 전환된 Agents 창으로 에이전트 퍼스트 개발을 실천하는 단계별 플레이북 — 세션 관리부터 빌드 자동화, 팀 워크플로우까지

## 소요 시간

30~60분 (초기 설정 포함)

## 사전 준비

- VS Code 1.120 이상
- GitHub Copilot 구독 (또는 BYOK 모델 설정)
- Git 워크트리 사용 가능한 레포

## VS Code Agents 창이란?

Agents 창은 VS Code 편집기 창의 보완 도구입니다. 편집기 창이 단일 워크스페이스의 코드 작업에 최적화된 반면, Agents 창은 **여러 레포와 세션을 넘나드는 에이전트 퍼스트 워크플로우**에 집중합니다.

VS Code 팀은 주간 릴리스로 전환할 만큼 Agents 창의 생산성 향상을 경험했고, 1.120에서 Stable로 공개했습니다.

## Agents 창 레이아웃

| 영역 | 위치 | 용도 |
|------|------|------|
| 세션 목록 | 사이드바 | 워크스페이스별 세션 보기 및 관리 |
| 커스터마이제이션 패널 | 세션 목록 하단 | 에이전트 동작 커스터마이징 |
| 채팅 영역 | 중앙 | 에이전트와 대화, 작업 지시 |
| 변경사항 패널 | 채팅 영역 하단 | 코드 변경 diff, 커밋, PR 생성 |

## Step 1: Agents 창 열기

```bash
# VS Code에서 Agents 창 열기
# 방법 1: 메뉴 > View > Agents Window
# 방법 2: 단축키 (설정에서 지정)
# 방법 3: 명령 팔레트 (Ctrl+Shift+P)
> Open Agents Window
```

Agents 창이 열리면 기존 세션 목록이 표시됩니다. 세션은 기본적으로 워크스페이스별로 그룹화됩니다.

## Step 2: 새 세션 시작

### 기본 세션 생성

```
Agents 창 상단 → + 버튼 → 새 세션 생성
```

세션 이름은 작업 내용을 반영하도록 지정하세요:

```
기능명-날짜 예: user-auth-2026-05-30
버그수정: fix-login-timeout
리팩토링: refactor-payment-service
```

### Worktree 기반 격리 세션

복잡한 작업은 Git worktree로 격리하면 main 브랜치에 영향 없이 진행할 수 있습니다:

```bash
# 세션 시작 전 worktree 생성
git worktree add ../my-project-feature feature/new-feature

# Agents 창에서 해당 worktree 경로 지정
```

Agents 창은 자동으로 worktree와 세션을 연결하여 변경사항을 격리합니다.

## Step 3: 에이전트에게 작업 지시

### 파일 탐색 패턴

```
이 레포의 인증 로직이 어디에 있는지 찾아줘.
주요 파일 구조를 파악하고 auth 관련 코드를 요약해줘.
```

### 기능 구현 지시

```
/create src/features/auth/login.ts

요구사항:
- JWT 기반 로그인
- refresh token 지원
- 에러 처리 포함
- 기존 코드 스타일 따를 것
```

### 빌드 자동화

에이전트가 코드 작성 후 즉시 빌드를 검증하게 합니다:

```
파일 작성 후 npm run build로 검증하고,
에러가 있으면 자동으로 수정해줘.
타입 에러도 포함해서.
```

## Step 4: 변경사항 검토

에이전트가 작업을 완료하면 변경사항 패널에서 확인합니다.

### Diff 보기

- **채팅 옆 diff 뷰 열기**: 변경 내용을 실시간으로 확인
- **모달 창**: 집중 검토가 필요할 때

### 피드백 추가

파일 내에서 직접 피드백을 입력할 수 있습니다:

```
파일 내 변경사항 클릭 → Add Feedback 선택
→ 에이전트가 다음 반복에서 반영
```

### 변경사항 처리 옵션

| 옵션 | 설명 |
|------|------|
| 커밋 | 현재 변경사항 바로 커밋 |
| worktree 머지 | 격리된 변경사항을 메인 브랜치에 병합 |
| Copilot Cloud 브랜치 체크아웃 | 클라우드 작업 로컬 가져오기 |
| 편집 버리기 | 전체 취소 |

## Step 5: 에러 수정 루프

Agents 창의 핵심 강점은 빌드/테스트 실패를 자동으로 처리하는 루프입니다.

### 태스크 실행 연동

```
코드를 작성한 후:
1. npm run test 실행
2. 실패한 테스트 목록 확인
3. 각 실패 원인 분석
4. 수정 후 재검증
5. 전부 통과할 때까지 반복
```

### 자동 에러 수정 패턴

```
TypeScript 빌드 에러, ESLint 경고, 테스트 실패를
모두 수정하고 clean build가 될 때까지 반복해줘.
각 단계에서 무엇을 수정했는지 요약해줘.
```

## Step 6: PR 생성까지

에이전트와 함께 PR을 생성하는 전체 흐름:

```bash
# 1. 에이전트가 코드 완성
# 2. 자동 테스트 통과 확인
# 3. 변경사항 패널에서 커밋 선택

# Agents 창에서:
"변경사항을 커밋하고 PR을 생성해줘.
제목: feat: JWT 기반 로그인 구현
본문에는 주요 변경 사항과 테스트 방법을 포함해줘."
```

## 세션 관리 팁

세션 목록에서 우클릭으로 다양한 관리 작업을 할 수 있습니다:

| 작업 | 용도 |
|------|------|
| 이름 변경 | 작업 내용 명확히 표시 |
| 완료 표시 | 마무리된 세션 정리 |
| 핀 | 자주 참조하는 세션 고정 |
| 삭제 | 불필요한 세션 제거 |

## 팀 워크플로우 패턴

여러 개발자가 Agents 창을 사용할 때의 권장 패턴:

### 세션 명명 규칙

```
팀원이름-기능-날짜: kim-payment-0530
이슈번호-설명: issue-234-fix-auth
```

### 병렬 작업 분리

```
개발자 A: Agents 창에서 API 레이어 구현 세션
개발자 B: Agents 창에서 UI 컴포넌트 세션
→ 각자 독립 worktree, 충돌 없이 작업
→ 완료 후 메인 브랜치에 순서대로 머지
```

### 코드 리뷰 연동

```
PR 생성 후 Agents 창에서:
"이 PR의 리뷰 코멘트를 가져와서 
우선순위별로 수정해줘."
```
