## Part 1: `/code-review` — PR 인라인 코멘트까지 지원하는 리뷰 명령어

### 무엇이 달라졌나요

Week 27 가장 큰 변화는 `/simplify`가 `/code-review`로 완전히 대체된 것이에요. 단순 코드 정리 도구였던 `/simplify`와 달리, `/code-review`는 **버그 감지와 PR 인라인 코멘트 게시**를 핵심으로 삼아요.

기존 `/simplify`의 cleanup-and-fix 동작은 제거됐고, 대신 코드 정확성을 지정 노력 수준에서 분석하는 방식으로 새롭게 설계됐어요.

### 기본 사용법

```bash
# 현재 변경사항 리뷰 (기본 effort)
/code-review

# effort 수준 지정
/code-review medium
/code-review high

# GitHub PR에 인라인 코멘트 게시
/code-review high --comment

# 특정 파일만 리뷰
/code-review --file src/auth/middleware.ts
```

### PR 인라인 코멘트 연동

`--comment` 옵션을 추가하면 발견된 버그와 문제점을 GitHub PR에 직접 인라인 코멘트로 남겨요.

```bash
# PR 체크아웃 후
gh pr checkout 241

# high effort로 리뷰 + 코멘트 자동 게시
/code-review high --comment
```

### effort 수준별 분석 범위

| effort | 분석 범위 | 소요 시간 |
|--------|-----------|----------|
| `low` | 명백한 버그, null 참조, 타입 불일치 | 30초~1분 |
| `medium` | 로직 오류, 엣지 케이스, 성능 병목 | 1~3분 |
| `high` | 보안 취약점, 아키텍처 결함, 전체 흐름 검증 | 3~8분 |

### 기존 `/simplify`와의 비교

| 항목 | `/simplify` (구) | `/code-review` (신) |
|------|-----------------|---------------------|
| 목적 | 코드 정리 + 자동 수정 | 버그 감지 + 리포트 |
| 수정 여부 | 자동 수정 | 수정 없음, 리포트만 |
| PR 연동 | 없음 | `--comment`로 인라인 게시 |
| effort 제어 | 없음 | `low`/`medium`/`high` |

> **주의:** `/simplify`를 자주 쓰던 분들은 자동 수정 동작이 사라진 점을 꼭 확인하세요. 코드 수정이 목적이라면 `/edit` 또는 직접 대화를 사용해야 해요.

## Part 2: 백그라운드 세션 핀(Ctrl+T) — 장시간 에이전트 관리

### 핀 기능이란

`claude agents`에서 백그라운드 세션을 `Ctrl+T`로 핀 설정하면 세 가지가 달라져요.

1. **아이들 상태에서도 살아있음** — 일반 세션은 30분 이상 유휴 시 종료되지만, 핀 세션은 유지돼요
2. **업데이트 시 제자리 재시작** — Claude Code가 업데이트되면 핀 세션은 같은 위치에서 재시작해요. 세션 번호가 바뀌지 않아요
3. **메모리 압박 시 마지막 종료** — 메모리가 부족해지면 비핀 세션부터 종료되고, 핀 세션은 가장 나중에 해제돼요

### 사용 패턴

```bash
# claude agents 열기
claude agents

# 세션 선택 후 Ctrl+T로 핀 설정
# 핀된 세션 앞에 📌 표시 나타남

# 핀 해제
# 핀된 세션에서 Ctrl+T 다시 누르기
```

### 언제 핀을 써야 할까요

| 상황 | 핀 추천 여부 |
|------|------------|
| 빌드/테스트 자동화가 돌고 있는 세션 | ✅ 추천 |
| 장시간 마이그레이션 작업 세션 | ✅ 추천 |
| 잠깐 실행하는 단발성 태스크 | ❌ 불필요 |
| 탐색적 코딩 세션 | ❌ 불필요 |

장시간 백그라운드 작업을 맡긴 세션은 핀으로 고정해두면 업데이트나 메모리 부족 상황에서도 안전하게 유지돼요.

## Part 3: `/usage` 카테고리별 분석 — 뭐가 토큰을 쓰고 있는지 파악하기

### 새로 추가된 사용량 분석

`/usage` 명령어가 단순 총량 표시에서 **카테고리별 세분화**로 업데이트됐어요.

```bash
/usage
```

이제 아래 항목별로 사용량이 분리돼요.

| 카테고리 | 내용 |
|---------|------|
| 스킬(Skills) | SKILL.md 기반 스킬 실행 |
| 서브에이전트(Subagents) | `claude agents`에서 파생된 에이전트 |
| 플러그인(Plugins) | 설치된 플러그인의 툴 호출 |
| MCP 서버별 | MCP 서버 이름별 개별 사용량 |

### 비용 최적화에 활용하기

카테고리별로 분석하면 어디서 토큰이 새는지 바로 보여요.

```bash
# 비용이 많이 나오는 MCP 서버 확인
/usage

# 예시 출력
Skills: 12% (1,240 tokens)
Subagents: 45% (4,650 tokens)
Plugins: 8% (820 tokens)
MCP - github: 23% (2,370 tokens)
MCP - filesystem: 12% (1,240 tokens)
```

서브에이전트 비중이 높다면 병렬 실행 태스크를 줄이거나, MCP 서버별 사용량이 높으면 해당 서버의 호출 빈도를 CLAUDE.md에서 제한할 수 있어요.

## Part 4: 보안 수정 — 지금 바로 업데이트해야 하는 이유

Week 27은 보안 수정이 많아서 특히 업데이트가 중요해요.

### PowerShell 권한 우회 버그 수정

v2.1.149에서 수정된 PowerShell 버그는 샌드박스 환경에서 심각한 보안 취약점이었어요.

**수정 내용:**
- `cd..`, `cd\`, `cd~`, `X:` 같은 내장 cd 함수가 샌드박스 감지를 우회해 작업 디렉터리를 워크스페이스 밖으로 이동할 수 있었어요
- PowerShell prefix/와일드카드 허용 규칙이 네이티브 실행 파일에 적용되지 않던 문제
- `PWD`/`OLDPWD`/`DIRSTACK` 변수 추적값이 `cd`/`pushd`/`popd` 이후 오래된 값을 신뢰하던 분석 오류

### Git worktree 샌드박스 경계 버그

병렬 에이전트에서 Git worktree를 쓰는 경우 중요한 수정이에요.

```bash
# 이전: 워크트리에서 메인 레포 전체가 쓰기 허용됐음
# 수정 후: 공유 .git 디렉터리만 허용, hooks/와 config는 차단됨
```

### macOS Bash `find` 크래시 수정

대형 프로젝트에서 `find` 명령을 쓸 때 macOS 시스템 파일/vnode 테이블을 소진해 호스트 프로세스가 크래시되는 문제가 수정됐어요. 모노레포나 node_modules가 깊은 프로젝트에서 특히 주의하세요.

## Part 5: 기타 품질 개선

### GFM 체크박스 렌더링

마크다운 출력에서 체크박스가 이제 제대로 렌더링돼요.

```markdown
# 이전: 원시 텍스트로 표시됨
- [ ] 할 일
- [x] 완료된 항목

# 수정 후: 체크박스 UI로 렌더링
```

CLAUDE.md나 AGENTS.md에 체크리스트를 자주 쓰는 분들에게 유용해요.

### `/diff` 키보드 탐색

`/diff`의 상세 뷰를 이제 키보드로 스크롤할 수 있어요.

| 키 | 동작 |
|----|------|
| `↑`/`↓`, `j`/`k` | 한 줄씩 이동 |
| `PgUp`/`PgDn`, `Space` | 페이지 이동 |
| `Home`/`End` | 처음/끝으로 이동 |

대형 diff를 검토할 때 마우스 없이 키보드만으로 빠르게 탐색할 수 있어요.

### 자동 업데이트 개선

업데이트 실패 시 더 명확한 오류 메시지를 보여줘요.

- 네트워크 일시 오류 시 자동 재시도
- 실패 시 오류 카테고리와 OS 오류 코드 표시
- 업데이트 실패 시 현재 버전 표시
