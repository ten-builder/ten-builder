# Devin 2.0 실전 가이드 2026 — $20/월로 자율 AI 소프트웨어 엔지니어 제대로 쓰기

> 월 $500에서 $20으로 — Devin 2.0이 개인 개발자도 쓸 수 있는 자율 AI 엔지니어로 돌아왔다. Interactive Planning, Devin Search, Devin Wiki 세 핵심 기능과 Claude Code와의 역할 분담 전략을 정리한다.

## Devin 2.0이 달라진 것

Devin 1.0은 $500/월이라는 가격 탓에 대기업이나 스타트업 팀 단위로만 쓸 수 있었다. 2026년 Devin 2.0은 세 가지가 바뀌었다.

| 항목 | Devin 1.x | Devin 2.0 |
|------|-----------|-----------|
| 시작 가격 | $500/월 | $20/월 (Indie) |
| 계획 방식 | 자율 실행 (불투명) | Interactive Planning — 실행 전 계획 검토 |
| 지식 베이스 | 세션별 리셋 | Devin Wiki — 레포 지식 영속화 |
| 검색 | 없음 | Devin Search — 코드베이스 시맨틱 검색 |
| 멀티에이전트 | 단일 에이전트 | Devin이 Devin을 오케스트레이션 |

## 플랜 선택

| 플랜 | 월 비용 | 크레딧 | 사용자 | 적합 대상 |
|------|--------|--------|--------|-----------|
| Indie | $20 | 40,000 | 1 | 개인 개발자, 사이드 프로젝트 |
| Standard | $60 | 130,000 (공유) | 20명 | 소규모 팀 |
| Max | $200 | 450,000 (공유) | 20명 | 중규모 팀 |
| Enterprise | 협의 | 무제한 | 무제한 | 대기업 |

**크레딧 소비 기준 (실전 추산):**
- 간단한 태스크 (도구 호출 10회): 수백 크레딧
- 복잡한 태스크 (도구 호출 60회): 수천 크레딧

Standard 플랜은 팀원당 $3/월 수준이라 소규모 팀에서 효율이 높다.

## 핵심 기능 1: Interactive Planning

Devin 2.0의 가장 큰 변화는 **실행 전에 계획을 검토**할 수 있다는 것이다.

### 사용 방법

```
# Devin에게 태스크 요청
"결제 모듈의 웹훅 핸들러가 종종 타임아웃 나는 이유를 분석하고 수정해줘"

# Devin이 계획서 제출:
# 1. payment/webhooks/*.ts 파일 분석
# 2. 타임아웃 패턴 파악 (로그 분석)
# 3. 비동기 처리 개선 (Promise.allSettled 도입)
# 4. 재시도 로직 추가
# 5. 통합 테스트 작성

# 개발자 검토 후 승인 또는 수정 요청
"3번은 괜찮은데, 4번은 기존 재시도 미들웨어(retryMiddleware.ts) 써줘"
```

### Interactive Planning이 필요한 태스크

- 레거시 코드 대규모 리팩토링
- 외부 API 통합 (보안 민감)
- 데이터베이스 스키마 변경
- 멀티 파일에 걸친 기능 추가

### 건너뛰어도 되는 태스크

- 단순 버그 수정 (1-2파일 수정)
- 타입 오류, 린트 경고 해결
- 테스트 케이스 보완

## 핵심 기능 2: Devin Wiki

레포의 지식을 영속화하는 기능이다. Devin이 작업하면서 학습한 내용이 Wiki에 쌓이고, 다음 태스크에서 그대로 활용한다.

### Wiki가 자동으로 저장하는 것

- 레포 구조와 핵심 파일 역할
- 팀 코딩 컨벤션 (PR에서 리뷰 코멘트 학습)
- 환경 설정 방법 (온보딩 과정 기록)
- 자주 쓰는 패턴과 유틸리티 함수

### Wiki 직접 편집

```
# Devin Wiki에 수동 추가
"Wiki에 추가해줘: 결제 API는 항상 idempotency key를 포함해야 하고,
재시도 시 동일한 key를 재사용한다"

# 이후 모든 결제 관련 태스크에서 Devin이 이 규칙을 따름
```

### CLAUDE.md vs Devin Wiki 비교

| | CLAUDE.md | Devin Wiki |
|--|-----------|-----------|
| 관리 | 개발자 직접 작성 | Devin이 자동 업데이트 |
| 형식 | Markdown 파일 | Devin 플랫폼 내부 |
| 범위 | AI 에이전트 전반 | Devin 전용 |
| 학습 | 정적 (수동 업데이트) | 동적 (작업하며 자동 학습) |

두 가지를 병행하는 것이 좋다. CLAUDE.md에는 팀 전체 규칙을, Devin Wiki에는 Devin만 필요한 실행 지식을 저장한다.

## 핵심 기능 3: Devin Search

레포 전체를 시맨틱 검색하는 기능이다. "결제 관련 에러 처리 어디서 하지?"를 파일명이 아닌 의미 기반으로 찾는다.

```
# Devin Search 활용 예시
"결제 실패 시 사용자에게 이메일 보내는 코드 찾아줘"
→ payment/notifications/failureEmailSender.ts, hooks/usePaymentError.ts 반환

"인증 토큰 만료 처리 로직 어디 있어?"
→ auth/middleware/tokenRefresh.ts, api/interceptors/auth.ts 반환
```

대규모 레포(10만 줄 이상)에서 빠르게 컨텍스트를 잡을 때 효과적이다.

## 멀티에이전트: Devin이 Devin을 관리한다

2026년 3월 추가된 기능으로, Devin이 복잡한 태스크를 여러 Devin에 위임하고 결과를 취합한다.

```
# 오케스트레이터 Devin에게 요청
"결제 시스템을 마이크로서비스로 분리해줘:
 - 결제 처리 서비스
 - 알림 서비스
 - 감사 로그 서비스"

# Devin이 내부적으로:
# Worker Devin 1: 결제 처리 서비스 설계 + 구현
# Worker Devin 2: 알림 서비스 설계 + 구현
# Worker Devin 3: 감사 로그 서비스 설계 + 구현
# Orchestrator Devin: 인터페이스 통합 + 통합 테스트
```

**주의:** 멀티 Devin은 크레딧 소비가 빠르다. Standard 플랜 이상에서 사용을 권장한다.

## Claude Code vs Devin 2.0 — 역할 분담 전략

두 도구는 경쟁 관계가 아니다. 특성이 다르므로 조합해서 쓰는 것이 효율적이다.

| 기준 | Claude Code | Devin 2.0 |
|------|------------|-----------|
| 실행 환경 | 로컬 터미널 | 클라우드 (브라우저 접근) |
| 컨텍스트 | CLAUDE.md 기반 | Devin Wiki 자동 학습 |
| 감독 방식 | 실시간 관찰 | 비동기 (작업 위임) |
| 강점 | 빠른 반복, 코드 탐색 | 장시간 자율 태스크 |
| 비용 | 토큰 단위 | 크레딧 단위 |

### 추천 조합 패턴

**Claude Code로 설계, Devin으로 구현:**
```
# Claude Code로 아키텍처 설계 및 CLAUDE.md 작성
claude --print "결제 시스템 인터페이스 설계해줘" > design.md

# Devin에게 구현 위임 (수시간 걸리는 태스크)
"design.md 참고해서 결제 시스템 구현해줘. PR로 올려줘"
# → Devin이 비동기로 작업, PR 생성
```

**Devin으로 초안, Claude Code로 리뷰:**
```
# Devin이 PR 생성 후
# Claude Code로 빠르게 코드 리뷰
claude "이 PR의 보안 이슈 확인해줘: [PR URL]"
```

## 실전 워크플로우: 기능 추가 시나리오

### Step 1: 태스크 정의

```markdown
## Devin 태스크 브리프

목표: 사용자 프로필 이미지 업로드 기능 추가

요구사항:
- S3 업로드 (presigned URL 방식)
- 이미지 리사이즈 (256x256, 512x512)
- 기존 이미지 삭제 처리
- 업로드 실패 시 롤백

제약:
- 파일 크기 5MB 이하
- JPEG, PNG, WebP 허용
- 기존 user 스키마 변경 최소화
```

### Step 2: Interactive Planning 검토

```
Devin 계획서 검토 포인트:
□ S3 퍼미션 설정 방법 (IAM 역할 vs 액세스 키)
□ 이미지 처리 라이브러리 선택 (Sharp vs Jimp)
□ 기존 코드와의 인터페이스 방식
□ 에러 케이스 처리 목록
□ 테스트 방법 (실제 S3 vs Mock)
```

### Step 3: 위임 및 모니터링

```
# Devin에게 승인
"계획 좋아. Sharp 써주고, 테스트는 aws-sdk-mock으로 해줘. 시작해"

# 비동기 작업 중 (1-3시간)
# Devin Wiki에 작업 과정 자동 기록
# 완료 시 PR 생성 + Slack 알림
```

### Step 4: PR 리뷰

```
# Devin이 생성한 PR 리뷰 시 확인 사항:
□ Interactive Planning에서 합의한 방식대로 구현됐는지
□ 에러 처리가 요구사항대로 됐는지
□ 테스트 커버리지 확인
□ 보안 이슈 (IAM 권한 최소화 여부 등)
```

## Devin 2.0이 잘 하는 것 vs 잘 못 하는 것

### 잘 하는 것

- PR 리뷰 코멘트 일괄 수정
- 레거시 코드 문서화
- 반복 패턴 리팩토링 (N개 파일 동일 수정)
- 테스트 케이스 보완
- 의존성 업그레이드 + 호환성 수정

### 잘 못 하는 것

- 모호한 요구사항 (명확한 스펙 필수)
- 실시간 상호작용이 필요한 디버깅
- 도메인 지식이 많이 필요한 비즈니스 로직
- 10만 줄 이상 대형 레포 전체 파악

## 시작하기 — Indie 플랜 추천 워크플로우

처음 4-6주는 작은 태스크부터 시작해서 Devin Wiki를 쌓는 것이 중요하다.

```
Week 1-2: PR 리뷰 코멘트 수정, 타입 오류 해결 (태스크당 10 ACU 이하)
Week 3-4: 단순 기능 추가, 테스트 작성 (태스크당 30 ACU 이하)
Week 5-6: 복잡한 기능 구현, Interactive Planning 활용 (제한 없음)
```

세션당 ACU 한도를 설정해두면 예산 초과를 방지할 수 있다.

```
# ACU 한도 설정 (Indie 플랜 기준)
Session ACU limit: 1,000 (전체 40,000의 2.5%)
```
