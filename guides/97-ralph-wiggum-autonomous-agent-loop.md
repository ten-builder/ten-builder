# Ralph Wiggum 패턴 — 단발 프롬프트에서 자율 에이전트 루프로

> 2026년 AI 코딩의 핵심 전환점 — "한 번 물어보기"에서 "스스로 완주하기"로

## Ralph Wiggum 패턴이란

Addy Osmani가 명명한 이 패턴은 2026년 AI 코딩의 가장 중요한 변화를 설명합니다.

**예전 방식:** 개발자가 AI에게 한 번 묻고, 결과를 받고, 다시 수정하며 반복.

**Ralph Wiggum 패턴:** AI 에이전트가 스스로 계획→실행→검증→수정 루프를 반복하며 작업을 완주.

```
단발 프롬프트 방식:
개발자 → AI (질문) → 결과 확인 → 개발자 (수정) → AI (재질문) → ...

Ralph Wiggum 패턴:
개발자 → AI 에이전트 (목표 지정) → [계획 → 실행 → 검증 → 수정] × N → 완료
```

이름의 유래는 심슨 캐릭터 Ralph Wiggum처럼 "그냥 해버리는" 특성에서 왔습니다.

## 소요 시간

설정 30분, 이후 에이전트 자율 실행

## 사전 준비

- Claude Code 또는 Codex CLI 설치
- 작업 레포에 CLAUDE.md 설정
- 명확한 목표 정의 (스펙 문서 또는 이슈)

## Step 1: 목표 기반 프롬프트 설계

단발 프롬프트와 자율 루프용 프롬프트의 차이는 **종료 조건** 명시입니다.

**단발 프롬프트 (안티패턴):**
```
"user authentication 기능 추가해줘"
```

**Ralph Wiggum 패턴 프롬프트:**
```
목표: user authentication 기능 구현
완료 조건:
- 이메일/비밀번호 로그인 동작
- JWT 토큰 발급 및 검증
- /api/auth/login, /api/auth/refresh 엔드포인트
- 단위 테스트 커버리지 80% 이상
- 기존 테스트 모두 통과

실패 시 복구 전략:
- 테스트 실패 → 원인 분석 후 수정 재시도
- 타입 에러 → 타입 정의부터 수정
- 의존성 충돌 → package.json 확인 후 호환 버전 사용
```

## Step 2: 자율 루프 구성 요소

성공적인 Ralph Wiggum 패턴의 4가지 핵심 요소:

| 요소 | 역할 | 구현 방법 |
|------|------|----------|
| **계획 단계** | 태스크 분해, 의존성 파악 | `/plan` 또는 Think 모드 활성화 |
| **실행 단계** | 코드 작성, 파일 수정 | 에이전트 자율 실행 |
| **검증 단계** | 테스트 실행, 린트 체크 | 터미널 명령어 실행 |
| **수정 단계** | 에러 분석 후 재시도 | 자동 에러 복구 패턴 |

## Step 3: CLAUDE.md에 루프 종료 조건 정의

```markdown
## 자율 실행 가이드라인

### 완료 조건
- 모든 테스트 통과 (`npm test` exit code 0)
- 타입 체크 통과 (`npx tsc --noEmit` 에러 없음)
- 린트 통과 (`npm run lint` 에러 없음)
- 명시된 기능 동작 확인

### 재시도 허용 횟수
- 같은 접근법으로 최대 2회 재시도
- 2회 실패 시 → 다른 접근법 시도
- 3회 이상 실패 시 → 체크포인트 저장 후 사용자에게 보고

### 금지 사항
- 테스트 코드 삭제로 통과시키기
- 타입 에러를 any로 무시하기
- 기존 기능을 변경하여 새 기능 추가하기
```

## Step 4: 에러 복구 루프 구현

```bash
# 에이전트가 자율 실행 중 에러 감지 시
while [ $RETRY_COUNT -lt 3 ]; do
  npm test 2>&1
  if [ $? -eq 0 ]; then
    echo "테스트 통과 — 완료"
    break
  fi
  
  # 에러 로그 분석 → 수정 → 재시도
  RETRY_COUNT=$((RETRY_COUNT + 1))
done
```

에이전트는 이 패턴을 내부적으로 구현합니다. CLAUDE.md에 명시하면 더 일관되게 동작합니다.

## Step 5: 결과 검증 및 핸드오프

루프 완료 후 개발자가 확인할 체크리스트:

- [ ] 모든 테스트 통과 확인
- [ ] 코드 리뷰 (AI가 생성했더라도 반드시 검토)
- [ ] 엣지 케이스 수동 테스트
- [ ] 보안 관련 코드 특별 검토
- [ ] PR 생성 전 diff 전체 확인

## 자주 하는 실수

| 실수 | 증상 | 해결 |
|------|------|------|
| 종료 조건 미명시 | 에이전트가 임의로 완료 선언 | 구체적 검증 기준 추가 |
| 복구 전략 없음 | 같은 실수 반복 | 실패 패턴별 대응 정의 |
| 컨텍스트 오염 | 루프 후반 품질 저하 | 주기적 컨텍스트 리셋 |
| 과도한 자율성 | 의도치 않은 코드 변경 | 허용 파일/디렉토리 명시 |
